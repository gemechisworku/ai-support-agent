How production voice agents for banking are built

Research findings · 5 November 2026 · Basis for a proof of concept on a single Mac (Apple M4, 16 GB)

Production voice agents for lenders and banks have settled on a common shape: a telephony edge, a real-time media pipeline, an LLM that is constrained by a script-like state machine, a narrow and audited gateway to bank data, a retrieval-backed policy knowledge base, and compliance rules enforced in code rather than in the prompt. Almost every piece of that stack now has a mature open-source option.

2What matters most in practice

Latency drives perceived quality. The usual target is about 800 ms from when the caller stops speaking to the agent’s first audio: roughly 50 ms capture, 150 ms STT, 400 ms LLM to first token, 150 ms TTS to first audio and 50 ms network. In practice, one analysis of over two million production calls found median response times of 1.4–1.7 s, so teams track P50/P90/P99 per stage. Fast responses depend on streaming at every stage, so TTS starts speaking on the first sentence while the LLM is still generating.

Turn detection matters more than raw speed. Silence thresholds alone either cut people off or add 800 ms or more of dead air. Model-based end-of-turn detection, which combines VAD with a semantic “has the caller finished?” check, fires in 200–400 ms. Barge-in needs echo cancellation, a probability-based VAD such as Silero, and immediate TTS cancellation.

Deterministic structure with a conversational surface. Collections calls follow a regulated sequence: identify the right party, give the required disclosure, state the balance, discuss and capture a promise to pay. Vendors model this as a state machine (or several hand-off agents) with the LLM handling language inside each state. They do not leave it to one free-form prompt.

Compliance is the design specification. In the US, for example, debt-collection law (FDCPA) applies to an AI caller exactly as to a human one, including the “mini-Miranda” disclosure. Regulation F presumes harassment above 7 call attempts in 7 days per debt, or any call within 7 days of a conversation, and restricts calls to 8 am–9 pm local time. In February 2024 the FCC ruled that AI-generated voices are “artificial voices” under the TCPA, so outbound AI calls need prior consent. Production systems enforce these rules in the dialer and the gateway, before the model is involved. An oral dispute stops collection and goes to a human, and the agent never argues. Rules differ by country, so the POC keeps them as configurable policy.

Identity before data. No account details are given until the right party is verified (for example date of birth plus the last four digits of the account). If a third party answers, the agent leaves only a neutral callback message.

3How they are deployed and managed

  • Stateless, horizontally scaled workers: a dispatcher assigns each call to a containerised agent worker, and capacity is planned in concurrent calls. Media servers run close to the carrier to keep latency low.
  • Versioned behaviour: prompts, scripts, disclosures and policy documents are versioned together and rolled out with canaries. Each call records the versions it used.
  • Testing with simulated callers: before a release, an LLM plays customer personas (angry, confused, hardship, wrong person) through hundreds of scripted conversations, and an LLM judge checks that the agent followed the rules.
  • Human oversight: live dashboards, sampled human QA of recordings, escalation queues, and outcome analytics such as right-party contact rate, promise-to-pay rate and promises kept.
  • Data protection: PII is redacted from logs and traces (for example with Microsoft Presidio), recordings are encrypted, and the gateway and tools follow least privilege.

4What this means for the POC

Replicate the architecture, shrink the scale. Use the open-source path end to end: LiveKit server, agents and SIP for media and telephony, with Asterisk and free softphones standing in for the phone network. Run the models locally on the Mac’s GPU (whisper.cpp for STT, Qwen3 via Ollama for the LLM, Kokoro for TTS), with an optional hosted LLM for comparison. Put the mock core bank and the knowledge base in PostgreSQL + pgvector behind an MCP data gateway, and add Langfuse for tracing. Expect about 1.5–2.5 s per response locally, against roughly 1 s in production; that is fine for validating flows, tools and guardrails. Real phone numbers can be added later with a carrier SIP trunk and no architectural change.
